# 图片并发验证

轻页“其他设置 → 兼容与诊断 → 图片下载并发”可选择 4、8、12，默认 4。当前章、预加载、全文缓存共用这个上限；后台仍为忙时最多 1 张、空闲时最多 2 张。提高上限会立即调度排队图片，降低上限只等待现有任务完成。配置本机保存，不同步到其他设备。

## 真机对照方法

1. 固定设备、网络出口、书源版本、图片档位与 HTTP 兼容设置。选择同一章节，包含普通图片及需要图片脚本的章节各一组。全程直连，不切代理。
2. 分别选择 4、8、12，各重复至少三轮。每轮确认冷缓存：可使用不同但内容等价的章节，或清理缓存后等待最近阅读保护期结束；以日志“缓存命中 0 张”为准，不把缓存命中的结果算作下载提速。
3. 每档分别测“直接打开章节”“上一章仍在预加载时翻章”“快速跨章后返回”。翻章时观察屏幕可见图片是否长时间等待；中途切换并发，确认不丢图、不重启已下载图片。
4. 收集 `[ReaderImageTiming]`：首张、整章、缓存命中、失败数、累计下载、脚本（含排队）、解密耗时。同时记录 UI 卡顿、内存峰值和服务端 403/429 等失败。
5. 按场景取中位数；单独列出慢图或错误。若并发变高导致失败率、内存或首屏等待明显增加，就调回 4。不同站点结果不可互相外推。

累计下载/脚本时间是各任务耗时之和，不等于整章墙钟时间；没有真机采样就不宣称固定倍数收益。脚本在高并发下排队、像素解码内存以及 CDN 限流都可能成为新瓶颈。

## 自动回归

```powershell
node scripts/reader-image-scheduler-check.mjs
node scripts/reader-image-results-check.mjs
node scripts/comic-image-pipeline-check.mjs
node scripts/network-settings-check.mjs
```

调度回归覆盖三档上限、后台先到时的前台保留空位、可见/附近优先级、翻章提权、取消、异常归还及运行时调高/调低上限；图片处理回归覆盖缓存、解密和内嵌图。Node 使用系统接口替身，不能替代上述真机测量。
