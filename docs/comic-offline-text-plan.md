# 漫画离线文字处理分阶段实施计划

日期：2026-10-23。状态：实施中，分支 `codex/comic-offline-text`。

## 调整后的计划与进度（2026-10-23 第二轮）

原计划阶段 0～5 保留在下文作为验收参考；按已有代码与本机 SDK 重新排了实施顺序：

| 批次 | 内容 | 状态 |
| --- | --- | --- |
| A | 长按「查看本页文字」：本机 OCR 全文、繁→简文本预览、复制 | 已完成（首轮） |
| B | 阅读页内繁→简图上改写：本书开关、纯色气泡覆盖重写、复杂背景保留原字 | 已完成，待真机 |
| C | 真机样本调参：底色阈值、字号、竖排、长图分段边界、与超分同开的耗时 | 待用户真机 |
| D | 日／英／韩→中：自带推理引擎与模型、模型导入／下载与校验 | 待用户决定路线 |

与原计划相比的取舍：

- 开关做成按书（书籍变量 `readerComicTextConvert = t2s`），放在漫画「画面」设置面板，默认关闭；不做全局默认，避免日漫、英漫每页白跑 OCR。
- 文字层不生成新图片：识别结果按原图像素坐标给出一组「底色块＋简体字」，在图片项里按显示尺寸叠加。条漫、翻页、双页、适应屏幕和双指缩放都随图片一起变换，没有额外图片缓存，也不和超分结果互相覆盖（文字层在超分图之上）。
- 只重写转换后有变化的行。同一文字块先整块转换再按原行切回，跨行词组也能匹配；含假名的行视为日文不转换。
- 识别时从 OCR 输入切片取每行外框一圈与框内像素：外框基本同色、框内除笔画外基本是底色，才判为可覆盖，并沿用原字颜色；网点、渐变、色块上的字保留原样，可在「查看本页文字」里看简体。系统 OCR 不给置信度，这里也不伪造。
- OCR 缓存键改为来源标识（本地路径＋大小＋修改时间，网络地址），网络图命中缓存不再重新下载；缓存版本 v2 带区域分组与颜色。系统服务连续使用期间保持初始化，空闲 30 秒释放；服务出错时释放、下次重建。
- 本机 API 26 SDK 没有公开的端侧文本翻译接口（Core Vision 只有 OCR、超分、文搜图等；`AICaption` 只用于音视频字幕）。日英韩→中必须自带推理引擎与模型，见下方「翻译路线待定」。

### 翻译路线待定

两条可行路线，都不上传内容：

1. **llama.cpp（NAPI 原生模块）＋小型多语种指令模型（GGUF 4bit）**：一个模型覆盖日英韩，可带前文和人名术语表；模型 1～2 GB，12 GB 机型可跑，速度需真机实测。
2. **MindSpore Lite ＋ 每语种一个专用翻译模型（Marian 类）**：单个模型较小，但需要转换为 `.ms`、在 ArkTS 实现分词与解码；日／韩→中的公开小模型质量偏弱，三语要维护三套。

另需确定模型来源：用户本地导入，或从你自己的服务器下载（国内直连 Hugging Face 不稳定）。选定前不接入任何翻译代码，也不做占位译文。

## 首批实施进度（2026-10-23）

- 已核对本机 API 26 SDK：`textRecognition` 支持繁体、日、英、韩，提供行坐标，没有置信度字段；使用的接口可兼容工程现有最低 API 20。
- 已加入漫画长按菜单「识别文字／繁→简」（第二轮改名为「查看本页文字」）及独立结果页，支持查看原文、繁→简文本预览、复制、取消和重新识别。原有保存／分享／重新加载入口保留。
- 已实现串行 OCR、带重叠的长图分段、原图坐标映射、内容摘要及系统版本校验的 OCR 缓存、离页取消和原生资源释放。网络来源只下载原图；本地来源不触发下载。
- 首批繁简预览采用 OpenCC ver.1.1.9 原始字典的轻量 ArkTS 最长匹配适配器，未引入完整 C++ 引擎；原始文件、校验摘要及 Apache-2.0 许可随包保留。
- 已有四类样本基准和模型对比仍待建立；没有宣称 OCR 漫画识别率、NPU 加速或真机性能达标。当前阶段 0／1 仅部分完成，阶段 2 只有文本预览，尚未图上回填（第二轮已补上，见上节）。
- 本轮不实现三语翻译占位输出；结果页明确说明外语翻译尚未开放。后续先完成样本／真机验证，再实现气泡清理回填与离线模型引擎。
- 检查记录见 `docs/comic-offline-text-verification.md`。

## 目标与边界

- 在设备本地完成繁体→简体、日文→简体中文、英文→简体中文、韩文→简体中文。
- 原图、OCR 文本和翻译内容不发送到远端。模型可预置、本地导入或由用户主动下载，准备完成后断网可处理本地漫画。
- 本轮不包含 AI 着色。已有超分保持现有功能，仅验证新增文字层与其同时开启时的显示及资源竞争。
- 第一版优先处理对白和普通旁白。复杂艺术字、拟声词和复杂背景使用原文保留＋译文查看的降级方式，不承诺所有区域无痕回填。
- 默认关闭，提供当前页处理和本书自动处理；目标语言固定为简体中文。源语言可手动指定繁体、日文、英文、韩文，自动识别作为后续便利能力。
- 2026-10-23 用户决定：漫画繁→简为会员专享，口径同超分（任一有效档位）；到期保留本书开关，续费自动恢复。长按「查看本页文字」的识别原文不限会员，其中的简体预览限会员。

## 已确认的工程基础

- `entry/src/main/ets/core/book/ComicImagePipeline.ts`：原图下载、解密、落盘缓存入口，文字处理接在得到可读图片之后。
- `entry/src/main/ets/components/reader/ReaderComicView.ets`：`ReaderComicImageItem` 已有可见性检查、异步结果票据及叠层显示，可作为共享接入点。
- `entry/src/main/ets/components/reader/ReaderComicPagedView.ets`：需要覆盖单页、双页和左右阅读方向。
- `entry/src/main/ets/core/reader/ReaderComicSettings.ets`：设置序列化、默认值、备份恢复兼容入口。
- `entry/src/main/ets/core/book/ReaderCacheBudget.ts`：当前漫画缓存预算为 1 GiB。新增派生缓存必须有预算，模型包单独管理，避免被漫画缓存清理误删。
- 现有书源兼容层的 `java.t2s` 并未实现实际简繁转换，不能作为本功能转换器。本轮不顺带改变书源行为。
- 当前工程最低兼容版本为 API 20，目标 SDK 为 26。新增功能先单独检测能力；只有接口或部署实测要求时才调整兼容方案，不直接提升整个应用最低版本。

## 阶段 0：OCR 与本地模型可行性验证

目的：先验证系统 OCR 是否适合漫画，以及设备能否承受离线翻译，再确定完整实现的依赖。

工作：

1. 建立四组固定样本，每组至少 20 页：繁体漫画、日漫、英文漫画、韩文条漫。覆盖横排、竖排、注音、彩色背景、小字、倾斜文字、低清图和超长图；样本使用自制或许可素材。
2. 每组至少 10 页作为保留验收集。标注普通对白的文字、区域和阅读顺序，复杂艺术字单列统计。
3. 在调试入口调用系统 OCR，显示文字区域和识别结果；核实实际接口的语言、坐标、方向、错误码及离线行为。不假设接口一定提供置信度。
4. 比较原图识别与必要的局部缩放；超长图采用带重叠的分段识别，记录裁剪变换并去重，不直接套用超分的固定切片策略。
5. 评估两条离线翻译路线：一个支持日英韩的多语种小模型，或按语种加载的专用模型。验证许可证、权重来源、分词器、量化版本、Native 构建和模型加载。
6. 用人工校正的文字单独测翻译，避免把 OCR 错误算作翻译模型错误；再测端到端结果。
7. 12GB 设备作为基本目标、16GB 设备作为推荐目标；记录冷启动、热启动、每页耗时、峰值内存和持续运行状态。设备未到位时只报告已完成的构建验证，不宣称真机通过。

验收与决策：

- 普通对白初始质量目标：区域召回率 ≥95%、字符错误率 ≤5%，四种文字分别报告。这是待验证目标，不是当前效果承诺。
- 每种翻译语言至少人工检查 100 条对白，分别报告漏译、错译、人名不一致和可理解程度，选定模型前明确是否达到产品可用标准。
- 产出 OCR 兼容表、模型对比表和实测报告，固定模型及字典版本。
- 系统 OCR 不达标的语种，进入专用本地 OCR 适配验证；某个翻译模型不达标则更换候选，不以默认上传云端作为兜底。

## 阶段 1：公共处理流程与文字层

交付：能对当前漫画页离线 OCR、查看识别文字，读图和翻页仍正常。

工作：

- 建立图片→文本区域→文本处理→排版→显示的统一接口，繁简与翻译使用相同的区域 ID。
- 使用方向校正后的原图像素坐标作为基准；保存图片尺寸、文字多边形、方向、区域 ID、原文、目标文本和识别来源。显示时统一变换，适配缩放、留白、双页和条漫。
- OCR 使用原图或已记录变换的局部输入，避免直接依赖屏幕截图。图片不足清晰时允许局部重试，不默认先对整页超分。
- 图片按内容摘要标识；OCR、文字结果和渲染结果分开缓存。缓存键分别包含引擎／模型／字典版本、源语言、目标语言及布局版本；有上下文的翻译另包含实际上下文及术语表摘要。
- 同页任务去重，当前可见页优先；翻页、切书、修改设置后使旧任务失效。无法中断的原生调用完成后丢弃过期显示结果，并释放资源。
- 长时间计算放到工作线程或原生异步任务，控制解码像素、推理并发和峰值内存。模型文件不存入临时漫画缓存。
- 原图或已有超分图先显示，文字层随后更新。超分结果到达不能盖住文字层；资源调度先通过实测确定并发上限。

验收：

- 条漫、左右翻页、双页、旋转、缩放时文字位置正确；跨页边界不重复显示同一句。
- 快速翻页和切书不出现旧页文字；关闭功能立即恢复原有显示。
- OCR 失败、缓存损坏、无文本页面都可正常阅读；缓存重用不重复识别。

## 阶段 2：繁→简可用版

交付：第一个可以单独发布的功能，支持繁体漫画离线简化。

工作：

- 引入 OpenCC 正式词典及转换实现，优先验证 C++／NAPI 方案；普通繁→简作为默认，地区词汇改写不自动混入。
- 对完整对白区域做词组转换；没有变化的区域不重绘。
- 保守识别纯色气泡内部，清除文字区域后重排简体；支持横排、竖排、标点和字号自适应，不为了容纳内容无限缩小字体。
- 无法可靠清理的复杂背景保留原字，通过点按区域或当前页文本列表查看简体结果。没有置信度字段时使用可解释的区域检查及失败状态，不伪造置信度。
- 加入繁→简开关、当前页处理、原图对比、重试和清除处理结果；本书设置可覆盖全局默认。
- 图片导出继续明确区分原图与处理结果；第一版若不支持处理结果导出，则保持原图导出并说明，不把带译文的屏幕截图当作原图。

验收：

- OpenCC 词组样例通过；识别、转换、排版分别检查，避免把错误归因混在一起。
- 保留验收集的普通气泡无明显残字、越界及对白截断，复杂区域能可靠降级。
- 模型／字典准备完成后，在断网状态下冷启动并完成当前页及连续翻页处理。
- 旧设置迁移、重启、备份恢复、功能关闭和缓存清理正常。

## 阶段 3：离线模型管理与翻译引擎

交付：可加载、卸载和离线运行选定翻译模型，输出带区域 ID 的简体译文。

工作：

- 根据阶段 0 结果固定推理框架，提供独立 Native 模块和 ArkTS 接口，不把模型代码混入书源／QuickJS 模块。
- 模型清单包含版本、实际支持语言、文件列表、大小、摘要、许可证、分词器和提示模板版本。
- 提供本地导入；若提供主动下载，则显示容量，校验完成后原子安装，支持取消、失败恢复与删除。读取本地漫画并推理不依赖登录或联网。
- 加入模型按需加载、空闲释放、内存压力降级、磁盘空间检查；只加载当前所需模型。
- 输入使用固定任务模板和带 ID 的对白数据，限定输出中文及格式，正文作为数据处理，避免漫画内容被当作执行指令。
- 对缺失、重复、未知 ID、空译文、格式错误和超长输出进行校验；失败可有限重试，仍失败保留原图并提供重试入口。
- 按页及有限前文组织上下文；术语表固定人物译名。缓存需绑定实际使用的前文，不让相同页面在不同上下文下误命中。

验收：

- 日、英、韩三种输入均有真实离线模型输出，不能以占位翻译通过验收。
- 模型缺失、损坏、不兼容、内存不足时可恢复，阅读器不崩溃。
- 完成准备后断网冷启动、加载、翻译、卸载全流程通过；无内容上传、远程翻译及隐藏云端回退。
- 分别记录各语种质量、模型大小、峰值内存及冷／热耗时，性能结论仅覆盖实测设备。

## 阶段 4：日／英／韩→中完整接入

交付：三种语言可在漫画阅读中处理并显示简体中文。

工作：

- 共用阶段 2 的回填和对比界面，源语言支持按书指定；同页混合语言无法可靠识别时允许手动选择，不强行猜测。
- 日文重点处理竖排阅读顺序和注音；英文重点处理断词、全大写和标点；韩文重点处理长条漫分段、跨块区域和对白合并。
- 译文按区域 ID 回填；超过气泡容量时重新断行、有限调整字号，仍容纳不下则显示完整译文面板，禁止静默截断。
- 对同书术语保持一致；不同书的上下文和术语隔离，清除结果与重新翻译的行为明确。
- 自动模式先限当前页及少量邻页，按优先级排队；翻页不等待推理完成。手动处理与自动处理复用任务。

验收：

- 三语分别运行保留验收集，记录端到端可读性、漏句、错位与术语一致性。
- API 返回成功不等于质量通过，保留人工对照结果；未达标语种不标记为正式支持。
- 快速跳页、倒序阅读、切换源语言、左右翻页与长条漫均无错页回填和缓存串用。
- 繁→简路径始终无需加载翻译模型。

## 阶段 5：性能、兼容与发布验收

交付：明确的设备支持范围、限制说明及可发布版本。

工作：

- 至少完成 12GB 与 16GB 真机测试，8GB 设备用于确认繁→简覆盖和翻译降级行为。建议测试组合为 Mate 70 Pro 12GB、Mate 80 Pro 16GB，具体以可用真机为准。
- 每台设备连续阅读至少 30 分钟或处理至少 50 页，记录发热／降频、耗电、峰值内存、队列积压、P50／P95 处理耗时及离开阅读器后的资源释放。
- 对普通页、超长条漫、小字页分别测量；性能结果固定模型、量化、输入尺寸、上下文长度与系统版本。
- 完成超分关闭／开启两组共存回归；文字处理不得破坏已有图片加载、翻页和原图导出。
- 检查模型缓存与漫画缓存分离、预算回收、应用升级、备份恢复和重启行为；模型权重默认不随普通阅读设置备份重复打包。
- 根据系统接口可用性、实际加载和运行测试决定能力开放，物理内存与机型名单只作为辅助条件。

发布门槛：

- 构建和相关回归检查通过；所有四条文字转换路径有离线真机证据。
- 连续阅读无崩溃、无不可恢复卡顿、无持续内存增长、无旧任务错页覆盖。
- 性能报告明确耗时和设备范围，不承诺未经测量的“每页秒出”。
- 模型／词典依赖版本、授权与文件校验信息完整，用户可以删除模型及处理缓存。
