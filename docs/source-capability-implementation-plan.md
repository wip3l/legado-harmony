# 书源能力改进实施计划

依据：2026-10-24 对四份外部建议的代码核对。按依赖顺序实施；外部文档中的性能数字不作为验收结果。

## 阶段 1：网络兼容与诊断

- [x] HTTP/1.1 手动兼容开关，持久化并在首页加载前恢复。
- [x] HTTPS 的 GET/HEAD 在协议异常时至多降级一次；只有降级成功才短期记忆，按 origin 隔离，数量有上限、到期重试默认协议。文本与二进制路径一致。
- [x] 2300999 保留“内部错误”含义；区分 HTTP/2、超时、连接重置等，不把空响应归因为 DNS 污染。
- [x] 核对最终 URL：向原生脚本提供真实可观测的 finalUrl，无法确定时明确为空；不得把原始 URL 冒充最终 URL。覆盖 SDK 自动跳转、显式跳转和浏览器路径。
- [x] 网络策略、重定向、设置恢复回归及 ArkTS 编译。

## 阶段 2：受控并发与请求预算

- [x] 图片总并发提供 4/8/12 选项，默认保持 4；保留后台限额及前台空位，运行时切换不取消已启动任务。
- [x] 覆盖后台先到、翻章提权、可见图片优先、调低上限及取消；补充可复现的真机测速步骤，不承诺固定加速倍数。
- [x] http.all(list, { concurrency, timeout }) 与单请求 timeout，参数校验、总请求预算、按输入顺序返回，超时传到底层且不被自动延长。
- [x] 调度器、脚本宿主、桥接与持久化回归及 ArkTS 编译。

## 阶段 3：原生内联评论页

- [x] 明确 page/chapterPage 的规则与返回数据、大小预算、点击时段落上下文；正文加载时只准备入口，点击后按需求值和取评论。
- [x] 复用阅读器评论面板，支持 HTML 和数据注入、标题、半屏高度；补全取消、异常和上下文失效处理。
- [x] 明确本地页面 origin、Cookie、脚本桥接和网络权限，不依靠“同源即安全”的假设；数据注入防止 script 标签提前闭合。
- [x] 保留 paragraphUrl/chapterUrl 回退；旧宿主需有原有 URL 字段，不能承诺 page-only 书源被旧版接受。
- [x] 规则、执行、面板、限额与兼容回归；调试页可查看/预览结果；ArkTS 编译。

## 阶段 4：开发文档与整体复核

- [x] 更新公开书源开发文档及其入口，提供批量请求、内联评论和回退示例。
- [x] 澄清已有 HMAC、图片分片重排、data 图片、网络超时能力；补 AMP 分页接口排查提示。
- [x] 记录各阶段验证命令、结果和真机验证边界；检查现有书源回归及最终改动。

## 本次不采用的建议

- 删除后台配额：已有反例证明会让后来可见图片等待全部后台占位。
- 直接默认 12 并发、宣称 4.1 倍：缺跨站点及真机证据；用可选设置交付调节能力。
- 遇到一次 2300999 就永久记住域名、无条件多重试：可能误判并重复有副作用的请求。
- 只靠文本扫描禁止未声明 ctx：会误判合法作用域，保留现有运行错误信息。
- 通用镜像列表、裁剪/模糊：需要分别定义线路成功条件及图片输出语义，本次不将单站点需求直接升级为宿主默认功能。
