# 漫画着色：缓存提前命中与真机验证

第三项优化已实现：对当前进程内已经确认过内容的本地原图，命中已有着色 JPEG 时，不再读取原图、计算 SHA-256 或进入串行推理队列。缓存未命中仍由原队列执行，不增加原生推理并发。

## 文件身份与失效

子库新增 `ComicColorSourceCache`，记录本地路径到内容寻址 JPEG 的映射。键包含宿主缓存目录、着色版本和本地路径；普通路径和对应 `file://` URI 共用映射。原生 `fileStamp` 返回设备号、inode、文件大小、纳秒级 mtime 和 ctime 的字符串组合，避免 64 位字段经 JavaScript number 丢失精度。

完整读取前后的身份必须一致才登记映射。快速查询在异步检查结果文件前后都重新核对原图身份；同尺寸改写、原子替换、删除及改写后恢复 mtime 都会使映射失效。输出被清理或为空则恢复常规内容查询/重建。原生信息不可用、非普通文件、空文件、超过 30 MB 或 ctime 没有小数精度时，保守地读取原图并计算哈希。

快速返回前仍检查会员、前后台、取消和视口就绪条件，返回时通知宿主更新结果最近使用时间。HTTP(S)、data URI 和内容提供者 URI 不建立来源快捷映射，同 URL 内容变化仍按重新取得的内容哈希处理。无需修改宿主接口或原 JPEG 文件名。

映射只在进程内保留最近 256 项，不保存图片字节、不落盘。重启应用后，首次访问每个来源仍需读取和哈希。这个范围是“已验证的本地缓存快速命中”，不是永久信任本地路径或远程 URL。

## 真机对照

- 设备：HOP-AL10，API 26，系统 `7.0.0.109(SP6C00E105R4P4)`，NNRT 设备名包含 Kirin9030Pro。
- 应用：4.4.931 调试构建，真实账户权限；测试前台运行、保持窗口亮屏，结束后恢复窗口属性。
- 基线保留前两项优化（原生补白/裁剪及 CPU 模型复用），使用原来的缓存查询实现；在任务独立源码目录构建，没有回退用户工作区。
- 顺序为基线、优化版、基线、优化版。每轮 10 次空闲缓存命中，交替使用本地路径和 file URI；同版本合并 20 次计算中位数。
- 使用设备中已有的 1350×1920 专用测试 JPEG。加入单字节 JPEG 注释构造大小相同、内容哈希不同、解码像素相同的 A/B 两个版本，没有读取用户书库。
- 计时为调用生产 `ComicColorizer.colorize` 到获得结果 URI，不包括 UI 图片加载和显示。`Date.now()` 分辨率为 1 ms，原始记录 0 ms 表示调用在同一计时刻度内完成，不代表零开销。

| 情况 | 基线 | 优化版 |
| --- | ---: | ---: |
| 空闲缓存命中，中位数（各 20 次） | 2.5 ms | 小于 1 ms（记录为 0） |
| 人为占用共享队列 1 秒，第一轮 | 1011 ms | 小于 1 ms |
| 人为占用共享队列 1 秒，第二轮 | 1064 ms | 小于 1 ms |
| 另一张图实际推理中，第一轮 | 1587 ms | 小于 1 ms |
| 另一张图实际推理中，第二轮 | 2677 ms | 小于 1 ms |

两种忙碌场景都直接检查“缓存返回时原任务是否仍未结束”：基线均为否，优化版均为是。实际推理任务随后正常完成。优化版全部 20 次空闲命中均未进入原图读取阶段；Node 回归另检查实际源码路径没有调用读字节和哈希函数。

主要收益是回翻时不必等待另一张图算完；空闲时原有查询已经是毫秒级。这项优化不减少首次页面的模型计算时间。上述数据仅针对本机和这份素材，不是所有设备或所有图像大小的保证。

## 正确性验证

- 四轮都通过同大小改写、恢复 mtime、原子替换、原图删除、着色 JPEG 删除后重建，以及路径/file URI 等价命中检查。
- 最终补充测试先给 B 设置固定的毫秒级 mtime 并建立映射，再改写为 A 并设置完全相同的 mtime；正确重新读取并返回 A 的内容寻址结果，验证 ctime 变化仍能使旧映射失效。该轮还重新覆盖了实际推理期间缓存命中，返回耗时 1 ms，原任务仍在运行。
- 四轮及最终补测保存的结果 JPEG 均与基线逐字节一致，SHA-256 为 `9b690555bfd0a9beab09bf617aabcf85a3fd038522c658332374364b86da89a6`。
- 最终生产版本的 `nativeComposite`、`offlineInferenceCacheAndCancel` 和 `warmupLifecycle` 真机功能测试通过。原生合成 301324 个通道最大误差 0/255；补白/裁剪 9376035 个 Float32 值最大误差 0。
- 完整 AI 子库 Node 检查、主应用着色及宿主运行时检查通过。新增回归覆盖 IO 期间内容变化、会员/前后台/视口状态变化、缓存删除、远程同 URL 更新、原生信息不可用、目录/版本隔离及容量限制。
- 普通应用与测试 HAP 构建成功。优化版普通应用已覆盖安装到设备，保留用户数据；最后已启动 EntryAbility。

## 复现与原始资料

本地忽略目录 `output/comic-cache-20261024/` 保存 `baseline*.json`、`optimized*.json`、`final.json`、逐轮日志、结果 JPEG、构建/回归日志及 HAP。`summary.json` 由下列脚本生成，同时检查样本数、读取次数、队列是否仍忙和 JPEG 哈希：

```powershell
node scripts/comic-cache-report.mjs output/comic-cache-20261024
```

设备已有专用测试图、安装相应测试 HAP 且账户具备真实权限时，可运行：

```powershell
hdc -t <设备地址> shell aa test -b io.legado.read -m entry_test -s unittest ComicCacheTestRunner -s cacheLabel verify -s cacheFast true -w 240
```

`cacheFast` 是测试断言开关，不是生产功能开关。必须检查 `TestFinished-ResultMsg: PASS ComicCache`；Hypium 功能测试还须确认 `Failure: 0, Error: 0, Pass: 1`。设备日志与报告日期可能因设备时区不同而相差一天。

前两项优化的基准和边界见 [原生像素处理与模型复用实测](comic-runtime-optimization-20261024.md)。三项优化代码位于 AI 子库，主应用通过子模块指针引入，并保留本轮测试入口与报告。
