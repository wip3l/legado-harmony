# 漫画离线文字处理：检查记录

日期：2026-10-23；分支：`codex/comic-offline-text`。

## 可操作范围

- 漫画阅读页 → 设置 → 画面 →「本书繁→简」（会员专享，口径同超分；按书保存，默认关闭；非会员显示「开通会员」，到期保留开关值）：图片显示出来且在屏幕上时排队识别，纯色气泡里的繁体行用原底色盖住、按原方向和颜色写简体；网点、画面上的字保留原样。关闭开关立即恢复原图。
- 漫画图片长按 →「查看本页文字」：本机 OCR 全文、复制、取消和重新识别不限会员；简体预览限会员，非会员点「繁→简」跳到会员与账号页。
- 会员与账号页的权益对比表、会员权益页各加一行「漫画繁→简」。
- 日文／英文／韩文目前只识别，不翻译；翻译路线待定（见实施计划）。

系统 OCR 不支持、图片无法读取、划走或服务异常时继续显示原图。超分实现没有修改，文字层叠在超分图之上。

## 已执行的自动检查

- `node scripts/comic-text-check.mjs`：执行真实字典转换、几何计算、底色判断、文字层生成、OCR 服务适配和长按菜单代码，系统／文件 API 使用替身。覆盖字典 SHA-256、繁简词组和扩展字符、长图核心区覆盖、重叠归属和坐标映射；纯色底／RGBA 与 BGRA／网点／渐变／字压色块／异常步长的底色判断；只重写有变化且可覆盖的行、日文行不转换、跨行词组整块转换后切回、竖排拆字与外扩；来源标识缓存命中、网络图不重复下载、缓存损坏、文件变化和系统版本变化重新识别；服务复用与空闲释放、出错释放后重建、队列取消、读不到像素时不覆盖、缓存写失败、文件句柄与 PixelMap 释放；原有图片操作索引。
- `node scripts/reader-image-results-check.mjs`、`reader-cache-budget-check.mjs`、`comic-image-pipeline-check.mjs`：已有回归，通过。
- `hvigorw assembleHap --mode module -p product=default -p buildMode=debug --no-daemon`：编译通过；新增文件只有工程里普遍存在的 “Function may throw exceptions” 提示。

## 真机反馈记录

- 2026-10-23 第一次真机（《東京貧困女子》话001 第 34 页，竖排繁体）：孤立的列（「不行吗…」「困难了」）改写正常，多列对白气泡大都没改。用截图模拟列框复现：列宽约 29px、列距约 9px，判断底色时外圈落在相邻列的字上，被判为不纯。改为取外圈时跳过同切片其他行框（各外扩 12%）后，同一截图上这些对白列在 OCR 框外扩 0～6px 时基本判为纯白；缓存升到 v3，旧结果不再使用。另加 `[ComicText]` 日志：每页识别行数、改写行数、跳过行数、用时（不含原文）。
- 2026-10-23 第二次真机（同话第 36 页）：多数对白已改写，个别气泡只改了一列（「很容易壞掉耶—。」「壞了嗎!?」「眞~~的」）。字典含壞→坏、嗎→吗、眞→真。用模拟列框复现时这些列底色都能判出，所以推测两个原因：一是 OCR 把竖排破折号／波浪线认成片假名长音符「ー」，整行被当成日文跳过——日文判断改为只看假名字母，不含「ー」「・」；二是贴着气泡弧形边线的列外圈压到边线——判不出底色时借用间隔不超过 1.5 倍字宽的相邻行底色，仍须通过框内检查。缓存升到 v4。两条推测都还没在真机上确认。

## 已知边界

- 只覆盖与坐标轴对齐的行框；明显倾斜的行外框会混入画面，通常判为不纯而保留原字。
- SDK 的行顺序直接保留，未推断漫画分镜阅读顺序；切片边界使用行中心归属。
- 字体使用系统默认字体（中等字重），不模仿原图字体；艺术字、拟声词不处理。
- OCR 缓存放在 `comic_images` 目录，受漫画缓存 1 GiB 上限管理；首轮的 `ocr_v1_*` 缓存不再读取，随缓存上限清理。
- 不保证与完整 OpenCC 引擎的全部配置语义一致；当前是固定字典的词组最长匹配与第一候选转换。
