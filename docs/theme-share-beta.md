## 对 GPT 方案的修正与补充

1. **内置素材不打包**：自定义方案的大部分部件只是“来源主题 ID”，内置图片随应用安装。把封面图集、内置背景等复制进包既没必要，还会把付费主题素材带给没买的人。包里只放用户自己上传的图片（启动封面、阅读背景）和可选字体。“实际效果快照”因此也不需要，改为记录所需能力 `requires`，遇到新版本才有的部件提示更新应用。
2. **权限要查全部部件，不只是气泡**：现有“应用方案”只检查启动封面来源。导入时对 11 个部件来源和内置背景素材逐一检查，导入方没获得的换成默认主题并在预览里列出，杜绝用手改的主题包绕过付费。规则里的气泡沿用阅读页运行时降级。
3. **会员门槛与 Beta 标识**：GPT 方案没有考虑；面板标题带 Beta。
4. **全局字体**：全局字体是整机设置，导入不应改动。导出时若正文/标题跟随全局字体且全局用的是自定义字体，改成直接绑定这款字体，导入后效果一致。
5. **压缩包安全**：系统解压接口不限制路径和体积，解压前先自行读 ZIP 中央目录（`ZipEntryInspector`），拒绝越界路径、重复条目、加密/ZIP64、超量条目和解压炸弹；解压后逐个核对清单里的大小、SHA-256 和文件头。
6. **分享通道**：除了保存到文件，还接了系统分享面板；声明了 `.qytheme` 文件类型（`utd.json5`）和“用本应用打开”，从聊天软件或文件管理器点开即进入导入流程。
7. **字体版权**：附带字体时提示“请确认字体允许分享”；丢失的字体只记名字，导入方退回全局字体。
   **只打包这套方案正在用的字体**（用户 2026-10-23 要求）：正文、标题（跟随全局字体时算全局那款），附带强调规则且规则总开关打开时再加规则用的字体；字体库里其他字体一律不带。导出面板逐款列出字体及用途（正文/标题/强调规则），关掉“附带强调规则”时只被规则用到的字体随之移出。
8. **署名清洗**：去掉换行、控制字符和改变书写方向的字符，限制 24 字；会员条款写明主题包不转让任何主题使用权。
9. **应用对话框的“应用主题排版”**：启用自定义方案时默认开启，表示“重置为预设”；用户可手动关闭，以使用方案自己保存的排版（包括导入方案的排版）。

## 文件格式（formatVersion 1）

ZIP 容器，扩展名 `.qytheme`：

```
theme/                 （系统压缩目录时带的顶层目录，导入时两种结构都接受）
├── manifest.json      format、formatVersion、packageId、name、author、exportedAt、appVersion、requires、assets[]
├── theme.json         settings（AppThemeSettings，图片换成 qytheme-asset:<id>）、layout、emphasis、fonts[]
└── assets/<sha256 前 24 位>.<png|jpg|webp|gif|bmp|ttf|otf|ttc>
```

- `requires`：`custom-scheme-v1`（必需）、`reader-layout-v1`、`emphasis-rules-v3`、`fonts-v1`。不认识的能力或更高的 formatVersion 一律提示更新应用。以后加底栏 SVG、朗读面板图片时，新增能力名和 `IMAGE_SETTING_KEYS` 槽位即可，格式不用换。
- 排版字段见 `LAYOUT_KEYS`：正文字号/字重/字距/对齐/行距/段距/缩进、四边边距、页眉页脚与进度条（含 `readerInfoBarConfig`）、正文/标题字体绑定与标题字号。翻页、手势、眼动等不随主题走。
- 上限：包 80 MB、解压后 160 MB、单张图片 20 MB、单个字体 40 MB、素材 24 个、规则 200 条。

## 代码位置

| 文件 | 作用 |
| --- | --- |
| `theme/share/ZipEntryInspector.ts` | 解压前检查 ZIP 中央目录 |
| `theme/share/ThemePackageFormat.ts` | 格式定义、清单/主题校验、部件替换、规则合并、字体重映射（纯逻辑） |
| `theme/share/ThemePackageService.ets` | 导出、保存/分享、导入预检、写入、导入图片清理 |
| `components/theme/ThemeShareDialogs.ets` | 导出面板、导入面板 |
| `pages/ThemeSettings.ets` | 长按菜单“分享主题包”、标题旁“导入”、详情页署名 |
| `utils/ReaderSettingsStore.ets` | `profileIdFor` 按方案拆档案，旧 `custom` 档案首次使用时复制 |
| `utils/CustomThemeSchemeStore.ets` | `author` 字段、`addImported`（占额度/替换）、`restoreActiveSchemeId` |
| `entryability/EntryAbility.ets`、`pages/Startup.ets`、`module.json5`、`rawfile/arkdata/utd/utd.json5` | 外部打开 `.qytheme` |

导入写入：图片按内容命名存到 `theme_startups/`、`reader_backgrounds/`（前缀 `qytheme_`），字体存到 `reader_fonts/` 并加入字体库（同内容复用）；新方案的阅读档案以当前档案（替换时为被替换方案的档案）为底，换上包内排版，规则追加在后。删除或替换方案后清理不再被引用的 `qytheme_` 图片。

1. 设备 A 导出（含上传的启动封面/阅读背景、自定义字体、强调规则、署名；字体库里另放几款未使用的字体，确认面板只列出、包里只带正在用的那几款）→ 保存到文件、系统分享都能成功；系统压缩出来的包能被自己导入（确认 `zlib.compressFile` 的条目结构被 `checkEntries` 接受）。
2. 设备 B 断网导入：预览列出被替换部件；导入后自动打开详情页，右下角显示 `author by xxx`；应用后启动封面、阅读背景、排版（缩进、页眉页脚）、字体、规则正确；重启后仍在。
3. 两套方案分别调不同的页眉页脚/缩进，来回切换互不影响；升级前已有的方案第一次使用时排版与升级前一致。
4. 冷启动：从文件管理器/聊天软件“用本应用打开” `.qytheme` 能进入导入；会员身份判断正确。
5. 额度已满时选择替换；正在使用的方案不在替换列表里；替换后旧图片被清理。
6. 非会员点击分享/导入出现会员说明；损坏文件、改了扩展名的普通 ZIP、手工塞入 `../` 路径的包都被拒绝且不留临时文件。
7. `utd.json5` 声明是否被系统识别（文件管理器里 `.qytheme` 的打开方式是否出现本应用）。
